## 1. 무엇을, 왜

연구 프로필을 한 번 입력해 두면 논문·저장소·뉴스·공고·공지를 한곳에 모으고, 사용자가 정한 시각에 새 소식만 알려 주는 데스크탑 앱이다.

해결하려는 불편은 네 가지다.

1. 논문, GitHub, 학회, 뉴스를 각각 다른 사이트에서 확인해야 한다.
2. 직접 찾아보지 않으면 모르고 지나간다.
3. 기존 알림과 피드는 양이 많고 무관한 것이 섞여 있다.
4. 국내 소식(학회, 과제 공고, 한국어 뉴스, 학교 공지)은 해외 도구로 잡히지 않는다.

사용자는 본인과 연구실 동료·지인 몇 명이다. 연구 분야가 서로 다르고, 개발자가 아닌 사람이 포함될 수 있다. 컴퓨터는 Mac과 Windows가 섞여 있다.

성공한 모습: 아침에 알림 하나를 눌러 한 화면 분량의 새 소식을 훑어보고, 여러 사이트를 돌아다니지 않는다.

## 2. 목표, 하지 않는 것, 피해야 할 것

**목표 (v1)**

- 프로필을 입력하면 카테고리별 새 소식 피드가 나온다.
- 이미 본 항목을 기억해 새 것만 보여 주고 알린다.
- 사용자가 정한 시각에 하루 한 번 묶어서 알린다.
- 카테고리를 골라 보고, 필요 없는 카테고리는 끈다.
- 사용자가 게시판 주소를 직접 추가한다.
- 핵심 참고문헌 찾기.
- 주제 추세 그래프.
- 지인이 설치 파일만으로 설치한다 (Mac, Windows).

**v1에서 하지 않는 것** [Claude 판단: 이후 후보로 미룸]

- AI 요약, 글로 정리한 동향 (사용자가 선택하지 않음)
- 저자·연구실 팔로우, 인용 알림
- 학회 마감일 D-day 달력
- BibTeX·노션·Zotero 내보내기
- 계정, 서버, 기기 간 동기화, 모바일
- 자동 업데이트, 코드 서명
- 한국 외 국가의 과제 공고 기본 출처, 한국어 외 화면 언어

**피해야 할 것**

- 하루에 여러 번 울리거나 항목마다 울리는 알림
- 이미 본 항목이 새 소식으로 다시 뜨는 것
- 지인에게 개발 도구 설치나 유료 가입을 요구하는 것
- 프로필이나 열람 기록을 조회 대상인 공개 출처 이외의 곳으로 보내는 것

## 3. 접근 방식

| | A. Electron 데스크탑 앱 | B. Tauri 데스크탑 앱 | C. 브라우저 확장 프로그램 |
|---|---|---|---|
| 알림 조건 | 컴퓨터가 켜져 있으면 항상 | A와 같음 | 크롬 계열 브라우저가 켜져 있을 때만 |
| 설치 | 설치 파일, 서명 경고 한 번 | A와 같음 | 링크로 추가 |
| 크기 | 약 100MB | 약 10MB | 1MB 미만 |
| 만드는 부담 | 중간 | 높음 (Rust 필요) | 낮음 |

**선택: A.** 사용자가 골랐다. 정한 시각에 알림이 뜨는 데스크탑 프로그램이라는 요청을 그대로 충족하면서, 전부 TypeScript와 React로 작성할 수 있어 부담이 가장 적다. B는 백그라운드 수집을 Rust로 써야 해서 이후 고치기 어렵고, C는 브라우저가 꺼져 있으면 알림이 오지 않아 요청과 다르다.

**과제 공고**는 국가가 한국일 때 IRIS와 한국연구재단의 공고 주소를 위 방식의 "미리 등록된 주소"로 넣는다. 공고 제목에는 연구 키워드가 거의 없으므로 키워드로 거르지 않고 새 공고를 모두 보여 준다. 두 사이트의 목록을 이 방식으로 읽을 수 있는지는 확인하지 못했다. 읽지 못하면 해당 사이트 전용 읽기 코드를 추가한다.

### 4.3 수집

- 시점: 앱을 시작할 때, 알림 시각, 사용자가 "새로 고침"을 누를 때.
- 각 출처의 결과를 공통 형태(카테고리, 출처, 제목, 주소, 날짜, 짧은 설명)로 바꾸고, 이미 본 항목을 뺀 뒤 저장한다.
- 같은 논문이 OpenAlex와 arXiv 양쪽에서 오면 하나로 합친다.
- 한 출처가 실패해도 나머지는 계속한다. 실패한 출처는 설정 화면에 표시한다.

**새 소식의 기준** [Claude 판단]

- 한 번 수집한 항목은 다시 새 소식이 되지 않는다.
- 사용자가 피드를 열어 항목이 목록에 나온 순간 그 항목은 "확인함"이 된다. "더 보기"에 접혀 있던 항목도 함께 확인함으로 친다.
- 피드의 "새 소식"에는 아직 확인하지 않은 항목이 날짜와 무관하게 쌓인다. 며칠 동안 앱을 열지 않으면 그동안의 항목이 모두 남아 있다. 확인한 항목은 "지난 소식"에서 최근 것부터 본다.
- 알림은 확인하지 않은 항목의 수를 센다. 지난번 알림 이후 새로 들어온 항목이 하나도 없으면 다시 알리지 않는다. 알림 시각 전에 피드를 이미 봤다면 그 뒤에 들어온 것만 알린다.
- 첫 실행 직후와 키워드를 바꾼 직후에는 논문·저장소·뉴스의 최근 결과를 새 소식으로 보여 준다. 빈 화면으로 시작하지 않는다. 게시판은 4.2대로 등록 시점의 글을 제외한다.


- 위쪽 칩을 눌러 카테고리별로 걸러 본다.
- 카테고리마다 관련도 상위 5건을 먼저 보여 주고 "더 보기"로 펼친다. 관련도는 키워드가 제목에 있는지, 얼마나 최신인지, 저장소라면 별 수로 정한다. AI는 쓰지 않는다. [Claude 판단: "놓친다"와 "너무 많다"를 함께 풀기 위한 방식]
- 항목마다 "저장"과 "관심 없음"이 있다. 저장한 항목은 저장 목록에서 다시 본다. 관심 없음은 그 항목을 숨긴다. [Claude 판단]
- 항목을 누르면 기본 브라우저에서 원문이 열린다.

### 4.5 알림

- 사용자가 정한 시각에 하루 한 번 알린다. 내용은 "새 소식 7건 (논문 3 · 저장소 2 · 학회 1 · 뉴스 1)" 형태이고, 누르면 피드가 열린다.
- 새 소식이 없으면 알리지 않는다.
- 그 시각에 컴퓨터가 꺼져 있었거나 잠자기 상태였으면, 다음에 앱이 실행되거나 깨어날 때 그날 분을 한 번 알린다. [Claude 판단]
- 창을 닫아도 앱은 메뉴 막대(Mac)나 트레이(Windows)에 남아 있고, 그 메뉴의 "종료"로 끝낸다. 로그인 시 자동 실행은 첫 실행 때 묻고 기본값은 켬이다. [Claude 판단: 정시 알림의 전제]

### 4.6 핵심 참고문헌 찾기

- 주제를 입력하면 인용 수가 많은 순으로 논문 목록을 보여 준다. "리뷰 논문만" 필터가 있다.
- 항목: 제목, 저자, 연도, 학술지, 인용 수, 원문 링크, 저장.
- 새 소식이 아니라 필요할 때 검색하는 기능이다. OpenAlex 키가 필요하다.

### 4.7 주제 추세 그래프

- 키워드별로, 최근 1년에 함께 많이 등장한 세부 주제 상위 10개와 전년 대비 증감을 보여 준다. [Claude 판단: "급상승 키워드"의 구체적 형태]
- OpenAlex 키가 필요하다.

### 4.8 화면 디자인과 디테일

> **2026-11-24 변경 (사용자 결정).** 아래 세 가지가 이 절의 이전 내용보다 우선한다. 이전 내용 가운데 이와 어긋나는 부분(보라~청록 색, 고리 모양 아이콘, "기다리는 동안에만 움직인다", "오브 외 애니메이션 없음", 큰 오브는 React Bits Orb)은 더 이상 유효하지 않다.
>
> 1. **색 조합은 차콜·앰버.** 바탕 `#1D1D21`, 주색 `#F1EFEA`, 강조색 `#F2A93B`. 앱 아이콘, 메뉴 막대·트레이 아이콘, 앱 안의 강조색, 오브가 모두 이 계열을 따른다. 밝은 모드에서 강조색이 글자·테두리로 쓰일 때는 대비 4.5:1을 넘는 더 짙은 앰버를 쓴다. [Claude 판단]
> 2. **앱 아이콘은 원자 모양.** 궤도 선은 주색, 핵과 전자는 강조색. 사용자가 "원자, 차콜·앰버"로 확정했다. 세부 형태는 궤도 세 개가 서로 겹치는 자리를 살짝 끊어 엮인 것처럼 보이게 하고, 핵 하나와 전자 하나를 강조색으로 둔다. [세부 형태는 Claude 판단] 메뉴 막대의 16픽셀 아이콘은 같은 모양을 단순화한다. [Claude 판단]
> 3. **오브는 생동감 있게 움직이고 마우스에 반응한다.** 사용자가 대화에서 본 견본을 승인했다: 점으로 이루어진 구가 천천히 돌며 숨 쉬듯 커졌다 작아지고, 마우스를 올리면 빨라지며 커서 쪽으로 기울고, 누르면 수집을 시작해 빠르게 돌며 물결치고, 끝나면 한 번 튀면서 새 소식 건수를 보여 준다. 위쪽 줄의 새로 고침 버튼 안(작은 크기)과 빈 화면(큰 크기)에 같은 오브를 쓴다. 완성도를 위해 목록·칩·버튼의 상태 변화에도 짧은 전환(0.15~0.2초)을 둔다. 운영체제의 "동작 줄이기"가 켜져 있으면 모두 멈춘다. [전환 시간과 적용 범위는 Claude 판단]


**방향 (사용자 결정):** 복잡하지 않고 담백하며 읽기 쉬운 화면. 로딩 스피너와 앱 아이콘 같은 작은 디테일을 공들여 만든다. 오브는 화면 배치의 중심이 아니라 이런 디테일에 쓴다. 참고한 것은 Thinking Orbs(thinkingorbs.com)와 React Bits Orb(reactbits.dev/backgrounds/orb)다.

**기본 화면** [Claude 판단]

- 배치는 4.4의 그림대로다: 위쪽 한 줄(제목, 새 소식 건수 요약, 새로 고침, 설정), 카테고리 칩, 목록. 큰 장식은 두지 않는다.
- 글꼴은 운영체제 기본 글꼴 하나만 쓴다. 줄 간격은 넉넉하게, 한 줄 길이는 읽기 편한 폭으로 제한한다.
- 강조색은 오브와 같은 보라~파랑 계열 하나다. 나머지는 무채색이다.
- 밝은/어두운 모드는 운영체제 설정을 따른다.

**오브를 쓰는 곳** [Claude 판단]

| 곳 | 모습 | 재료 |
|---|---|---|
| 수집 중 (새로 고침, 알림 시각의 수집) | 새로 고침 버튼 자리에서 작은 오브가 움직이고 옆에 "수집 중" | Thinking Orbs |
| 참고문헌 검색, 추세 그래프, 게시판 미리보기를 기다릴 때 | 결과가 나올 자리에 작은 오브와 무엇을 기다리는지 한 줄 | Thinking Orbs |
| 출처가 실패해 다시 시도할 때 | 설정 화면의 해당 출처 줄에 재시도 모양의 오브 | Thinking Orbs |
| 첫 실행 뒤 첫 수집을 기다리는 화면 | 화면 가운데 큰 오브와 "첫 소식을 모으는 중입니다" | React Bits Orb |
| 새 소식을 모두 확인한 빈 화면 | 멈춘 큰 오브와 한 줄 | React Bits Orb |
| 앱 아이콘 | 오브 고리 모양의 정지 그림 | 직접 그림 |
| 메뉴 막대·트레이 아이콘 | 작은 고리. 확인하지 않은 새 소식이 있으면 점 하나를 붙인다 | 직접 그림 |

알림 대체 창(9절)에도 앱 아이콘을 넣는다.

**오브의 규칙** [Claude 판단]

- 무언가를 기다리는 동안에만 움직인다. 끝나면 사라지거나 멈춘다. 글 목록 뒤에 깔지 않는다.
- 움직이는 오브 옆에는 무엇을 하는 중인지 글자를 붙인다. 화면 읽기 프로그램용 이름도 넣는다.
- 0.3초 안에 끝나는 일에는 오브를 띄우지 않는다. 잠깐 나타났다 사라지는 깜빡임을 막기 위해서다.
- 기다리는 동안 목록과 버튼의 자리가 밀리지 않게 한다.
- 창이 숨겨져 있으면 멈춘다. 운영체제의 "동작 줄이기"가 켜져 있으면 멈춘 모습으로 보여 준다.
- 큰 오브와 작은 오브는 같은 강조색을 써서 한 가족으로 보이게 한다.

**그 밖의 디테일** [Claude 판단]

- 누를 수 있는 것은 마우스를 올리면 반응하고, 키보드로 옮겨 다닐 때 초점이 보인다.
- 앱 아이콘과 트레이 아이콘은 시안을 사용자에게 보여 준 뒤 확정한다. Mac 메뉴 막대 아이콘은 단색 규격을 따른다.

## 5. 제약

- 프로필, 설정, 항목, 본 기록, 저장 목록은 각자 컴퓨터에만 저장한다. 서버는 없다.
- API 키는 그 컴퓨터에만 저장하고 운영체제의 보안 저장소로 암호화한다.
- 외부에서 온 글자(제목, 설명)는 항상 일반 글자로 표시하고 HTML로 해석하지 않는다. 화면 쪽 코드는 Node 기능에 직접 접근하지 못하게 격리한다. 여는 링크와 사용자가 등록하는 주소는 http와 https만 허용한다.
- 출처의 호출 한도를 지킨다.
- 화면 언어는 한국어다.

## 6. 기술 결정 [Claude 판단]

- Electron, TypeScript, React. 수집·저장·알림·트레이는 메인 프로세스가, 화면은 렌더러가 맡는다.
- 수집 결과 변환, 중복 제거, 새 글 판별은 화면과 분리된 순수 함수로 두고, 저장해 둔 실제 응답 파일로 자동 테스트한다.
- 저장소는 비공개로 둔다(사용자 결정). 배포는 서명 없는 설치 파일(Mac용 dmg, Windows용 exe)을 사용자가 지인에게 직접 전달한다(사용자 결정).
- Mac용은 사용자의 Mac에서 빌드한다. Windows용은 비공개 저장소의 GitHub Actions에서 빌드해 결과 파일을 내려받는다.
- 지인용 설치 안내 한 장을 만든다(서명 경고 창을 넘기는 방법 포함).
- 오브는 앱 안에 직접 만든 캔버스 컴포넌트(`LiveOrb`) 하나를 크기만 바꿔 쓴다(4.8의 2026-11-24 변경). 처음에 쓰던 Thinking Orbs와 React Bits Orb 파일·의존성은 참조 없이 남겨 두었고, 앱이 완성된 시점에 사용자 확인을 받아 지운다(사용자 결정 2026-11-24).
- 프로젝트 위치: `~/Desktop/se_labmate/` (git 저장소. 2026-11-25에 `research-assistant`에서 이름을 바꿨다. GitHub 저장소 이름과 앱의 데이터 폴더 이름은 `research-assistant` 그대로다).

## 7. 만드는 순서 [Claude 판단]

각 단계가 끝나면 그 상태로 쓸 수 있는 앱이 나온다.

1. 기본 출처 피드와 알림: 프로필, 논문·저장소·뉴스 수집, 본 것 기억, 카테고리 칩, 정시 알림, 수집 중 오브, 앱·트레이 아이콘. 본인 Mac에서 사용 가능. 끝나면 Windows 시험판을 만들어 지인에게 알림·트레이·자동 실행 확인을 부탁한다.
2. 게시판 감시: 직접 추가 출처, 과제 공고 기본 주소.
3. 핵심 참고문헌 찾기와 주제 추세 그래프.
4. 배포 마무리: 최종 설치 파일(Mac, Windows)과 설치 안내.

## 8. 만드는 사람에게 맡기는 것

- 저장 형식과 보관 기간
- 게시판에서 글 목록을 찾아내는 구체적 규칙. 다만 실제 게시판 5곳(IRIS, 한국연구재단, 국내 학회 1곳, 대학 공지 1곳, 연구실 홈페이지 1곳)으로 시험한다.

- 그래프를 그리는 방법
- 4.8에 적지 않은 시각 세부: 정확한 색 값, 간격, 오브의 상태별 모양 선택, 아이콘 그림의 세부

## 9. 확인되지 않은 것

- IRIS와 한국연구재단의 공고 목록을 게시판 감시 방식으로 읽을 수 있는지
- 게시판 감시 방식이 실제 학회·학교 게시판에서 통하는 비율
- 서명 없는 앱에서 Mac과 Windows 알림이 정상적으로 뜨는지 (1단계에서 가장 먼저 확인). 뜨지 않으면 정한 시각에 앱이 직접 작은 알림 창을 띄우는 방식으로 대체한다. 유료 코드 서명은 그것으로도 부족할 때의 선택지로 남긴다. [Claude 판단]
- Windows에서의 실제 동작. 본인 컴퓨터가 Mac이므로 지인이 시험한다(사용자 확인: 부탁 가능). 1단계 끝의 시험판으로 확인한다.
- 비공개 저장소의 GitHub Actions 무료 빌드 시간이 Windows 빌드에 충분한지
- React Bits Orb를 켜 둘 때의 부하. 무거우면 큰 오브도 Thinking Orbs를 크게 키워 대체한다. [Claude 판단]
- 두 오브가 Electron 화면에서 원하는 색과 크기로 그려지는지. 사이트에서 본 것이 전부이고 직접 넣어 보지는 않았다.
